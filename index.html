Understanding Page Replacement Algorithms

A comprehensive guide to virtual memory management, eviction heuristics, hardware trade-offs, and theoretical bounds.

FIFO (First-In, First-Out)

Queue Based

The operating system maintains a FIFO queue of all pages currently in memory. When a page must be replaced, the page at the head of the queue (the oldest loaded page) is chosen.

Time Complexity

O(1) with queue pointers / circular buffer.

Advantages

Extremely simple to implement with minimal hardware overhead. Requires only a queue of frame pointers.

Disadvantages & Limitations

May evict heavily used initialization modules or shared libraries simply because they were loaded early. Susceptible to Belady's Anomaly.

LRU (Least Recently Used)

Recency Based

Replaces the page that has not been referenced for the longest period of time, leveraging the principle of temporal locality (recent past predicts near future).

Time Complexity

O(1) per reference with doubly linked list & hash map; O(f) with scan.

Advantages

Consistently performs very well in general workloads. Mathematically proven to be a stack algorithm, completely immune to Belady's Anomaly.

Disadvantages & Limitations

Requires dedicated hardware support (timestamps or counter registers on every memory reference) to avoid significant CPU overhead. Real OS kernels use approximations like CLOCK or aging.

Optimal (Belady’s MIN)

Theoretical Benchmark

Replaces the page whose next reference occurs farthest in the future. If a page will never be referenced again, it is an immediate candidate for eviction.

Time Complexity

O(f · n) per reference simulation scan.

Theoretical Bound

Mathematically guarantees the minimum possible number of page faults for any fixed number of frames.

Practical Limitation

Unrealizable in general operating systems because an OS cannot foresee future page requests of arbitrary user processes. Used strictly as a gold standard to benchmark practical heuristics.
